* Source and dependency baseline

HPX is managed by the =3rd/hpx= submodule. The 2026-10-22 upgrade advances
upstream =master= from =6e97afa18a1a189d0147397ecb3400917aef2b94= to
=6456abf559aeaa05b7a1612d8f8dc59c8d6df511= without local upstream patches.
The source reports =2.0.0=; this is a pinned development snapshot, not a release tag.

The HPX builder pins fetched stdexec to the matching upstream baseline
=04de75de5807e73a229acf047c6976575e313359=. This still matches the new HPX
checkout, so no builder pin change is needed. Check the pair on each future
upgrade rather than retaining an obsolete override. C++20, static linking,
jemalloc, networking and the MPI parcelport
remain enabled. Upstream examples/tests remain disabled and tools remain enabled.

Source overrides (=ZETA_HPX_SRC_DIR= / =ZETA_3RD_DIR=) must select the intended
checkout. The installation prefix remains =ZETA_INSTALL_PREFIX=, defaulting to
=~/.local=. No proxy, application JSON or HPX INI settings are rewritten.

* Changes from the previous snapshot: 2026-10-22

The new snapshot includes TCP sender shutdown-race and background-thread cleanup
fixes, MPI/distributed-channel deadlock and initialization-ownership fixes,
timed-mutex/semaphore/stop-callback fixes, and work-requesting/NUMA scheduler and
future-child execution fixes. Networking and MPI remain enabled in Forge;
performance changes have not been benchmarked here.

This source update has not rebuilt or installed HPX or its consumers. The
2026-10-15 validation record below applies only to
=6e97afa18a1a189d0147397ecb3400917aef2b94=, not the current snapshot. See
[[file:third_party_usage.org][Versions and Updates]] for the current verification boundary.

* Consumer compatibility

The 2026-10-15 migration retained =as_sender=, =make_future= and
=thread_pool_scheduler=. The future sender implementation and completion
environment changed; =make_future=
now uses direct overloads and scheduler queries instead of tag-invoke customization.
zpp exposes the same =from_future=, =into_future= and scheduler interfaces.

zpp's =HPX_GIT_COMMIT= check verifies source/install provenance, not API
compatibility. Rebuild and reinstall HPX before configuring zpp, then reinstall
=zpp_hpx= so its exported package records the same revision. Rebuild statically
linked consumers against the new installation; do not reuse old binaries as
upgrade evidence. A scheduler-aware future conversion is required by the
single-worker cooperative-wait regression, rather than an OS-blocking wait.

Forge explicitly passes =HPX_WITH_GIT_COMMIT= and its short form from
=git rev-parse HEAD=. Upstream's path-filtered =git log= can skip a merge
commit and report its parent instead; recording that parent would incorrectly
fail zpp's exact-revision gate. This override also makes a source revision
change invalidate the configure arguments even when no watched CMake file changed.

* Release delivery and validation

Run each command only after the previous one succeeds. Shared Release
dependencies are prerequisites. Forge =build= stages locally; its =install=
publishes the selected successful build without rebuilding.

#+begin_src bash
cd "$ZETAX_ROOT/zeta_forge"
./zbuild.py test
./zbuild.py doctor hpx --profile release
./zbuild.py build hpx --profile release --jobs 4
./zbuild.py install hpx --profile release

cd "$ZETAX_ROOT/zpp"
./zbuild.py test zpp_hpx --profile release --jobs 4
./zbuild.py build example_hpx_basic zpp_hpx_basic zpp_hpx_exec_pipeline zpp_hpx_exec_scheduler --profile release --jobs 4
./zbuild.py run zpp_hpx_exec_pipeline --profile release
./zbuild.py run zpp_hpx_exec_scheduler --profile release
./zbuild.py install zpp_hpx --profile release --jobs 4

cd "$ZETAX_ROOT/zeta_trader"
./zbuild.py build zeta_trader_hpx --profile release --jobs 4
./zbuild.py test zeta_trader_hpx --profile release --jobs 4
#+end_src

The zpp entrypoint runs the configured core and HPX CTest correctness suite.
The execution tests cover shared-future reuse, values/void/move-only values,
exceptions, scheduler-aware pending futures and sender-to-future conversion.
Runtime tests run with two workers and one worker, each with a 15-second timeout.
The Trader test entrypoint runs its configured shared correctness suite; it is
broader than the selected service target and does not start a production stack.

Also configure and run a separate temporary CMake consumer of
=find_package(zpp_hpx CONFIG REQUIRED)= and =zpp::hpx=. Verify that an incorrect
expected HPX revision is rejected, and that the source, installed HPX package and
zpp export all record the same commit and the selected stdexec checkout matches
the builder pin.

These commands describe the acceptance procedure, not evidence that a run has
passed. Record actual results separately. Debug, sanitizers, performance/RSS
benchmarks, long stress runs and real Provider/HPX integration are outside this
Release acceptance. No trading connections, production restarts or frontend
rebuilds are required by this HPX-only upgrade.
