* Zeta Forge

Zeta Forge 是一个用于统一源码管理、可复现构建和依赖集成的 C++ 超级工程。

English README: [[file:../readme.org][../readme.org]]

* 项目用途

Zeta Forge 有三个明确用途：

1. 作为托管 =3rd/*= 源码项目，以及 =zpp= 这类外部 ZetaX 项目的共享编译工具链框架，统一提供 Conan/CMake/Ninja 编排、源码路径解析、安装前缀和可复用项目构建原语。
2. 协调工作区内各子项目版本，包括 submodule revision、第三方依赖版本、共享构建默认值和项目级构建配方。
3. 作为外部系统可复用的通用工具链框架。仓库外项目可以通过 =$ZETAX_ROOT/zeta_forge= 或附近的兄弟目录定位 =zeta_forge=，复用公共构建库，避免每个项目重复维护一套依赖和工具链。

* 克隆与初始化

建议在克隆时直接拉取全部 submodules：

#+begin_src bash
git clone --recurse-submodules <repo-url>
#+end_src

如果仓库已经克隆完成，可以再执行一次递归初始化：

#+begin_src bash
git submodule update --init --recursive
#+end_src

之所以要使用递归方式，是因为某些源码仓库自身也带有 submodules，例如 gRPC。

* Debian 系系统准备

在私有 ZetaX 环境中，环境准备可以拆成两层：

1. =zsa= 负责 Debian/Ubuntu 宿主机环境 bootstrap。
2. =zeta_forge= 负责仓库内部工具链和依赖准备。

如果 =zsa= 与 =zeta_forge= 以兄弟目录方式检出，可以先执行：

#+begin_src bash
../zsa/util/bootstrap_debian.sh --minimal
#+end_src

公共用户也可以手动准备同样的宿主机依赖，然后再执行 =zeta_forge= 仓库内准备脚本：

#+begin_src bash
./common/prepare_debian.sh
#+end_src

=./common/prepare_debian.sh= 专注于 =zeta_forge= 内部工具链管理：构建依赖、Conan 2 和 submodule 初始化。默认跟随 =zsa= 准备好的 ZetaX/uv Python 环境；只有项目确实需要固定 Conan Python runtime 时，才传入 =--python-version X.Y=。=zsa= 对公共用户不是必需前置条件。如果当前系统还没有 Python，这个 wrapper 会提示需要先安装的最小宿主机依赖；当存在兄弟目录 =zsa= 时，也会提示可选的 =../zsa/util/bootstrap_debian.sh --minimal= 辅助入口。

* 顶层统一构建入口

你可以直接在仓库根目录使用统一调度入口来触发构建：

#+begin_src bash
./zbuild.py grpc --rebuild --install
./zbuild.py hpx --rebuild --install
./zbuild.py all --rebuild
#+end_src

=zbuild.py= 中的 =z= 取自 =zeta_forge=，用于表达仓库顶层统一入口，而不是局限于 CMake 的 =c=。
=zbuild.py= 可以直接执行，并分发到 =builder/= 下对应项目的工作区目标入口。
当执行 =./zbuild.py all= 时，调度器会先构建 =grpc=，将 =hpx= 和 =nng= 视为相互独立的目标，然后在 =grpc= 后构建 =folly=。

* 源码布局

第三方源码目录位于 =3rd/= 下：

- =3rd/hpx=
- =3rd/folly=
- =3rd/grpc=
- =3rd/nng=
- =3rd/taskflow=
- =3rd/rapidjson=

外部 ZetaX 项目，例如 =zpp=，位于 =ZETAX_ROOT= 下与 =zeta_forge= 平级的位置，并把本仓库作为可复用工具链框架调用。
本仓库中的工作区目标入口默认都使用托管的 =3rd/*= submodules 作为源码输入。
工作区编排入口统一放在 =builder/= 目录下。

* ZetaX 工作区根目录

=ZETAX_ROOT= 是唯一公开的顶层工作区变量，例如 =~/git=。
标准布局中，=zeta_forge= 位于 =$ZETAX_ROOT/zeta_forge=，=zpp= 等外部项目位于 =$ZETAX_ROOT/zpp=。
=zsa= 可以在私有工作流中自动导出 =ZETAX_ROOT=，公共用户也可以手动设置。

项目入口需要复用共享编译工具库时，按以下顺序定位 =zeta_forge=：

1. 设置了 =ZETAX_ROOT= 时，使用 =$ZETAX_ROOT/zeta_forge=。
2. 从当前入口路径向上发现附近的 =zeta_forge= 目录。

* 覆盖源码目录

如果你希望使用自己的本地源码仓库，而不是 zeta_forge 管理的 submodules，可以在运行工作区目标入口前覆盖对应环境变量：

#+begin_src bash
export ZETA_GRPC_SRC_DIR=/path/to/grpc
export ZETA_HPX_SRC_DIR=/path/to/hpx
export ZETA_FOLLY_SRC_DIR=/path/to/folly
export ZETA_NNG_SRC_DIR=/path/to/nng
export ZETA_TASKFLOW_SRC_DIR=/path/to/taskflow
export ZETA_RAPIDJSON_SRC_DIR=/path/to/rapidjson
export ZETAX_ROOT=/path/to/zetax-workspace
export ZETA_3RD_DIR=/path/to/zeta_forge/3rd
export ZETA_INSTALL_PREFIX=/path/to/install/prefix
#+end_src

如果没有显式覆盖，第三方源码路径默认使用 =3rd/= 下对应的 submodule 路径。

=ZETA_INSTALL_PREFIX= 默认值为 =~/.local=。

* 工作区目标入口示例

#+begin_src bash
./builder/grpc/zbuild.py --rebuild --install
./builder/hpx/zbuild.py --rebuild --install
./builder/folly/zbuild.py --rebuild --install
./builder/nng/zbuild.py --rebuild --install
#+end_src

* 外部 zpp 入口

=zpp= 是位于 =$ZETAX_ROOT/zpp= 的独立 ZetaX 项目。它自己维护项目级 Builder 和 Conan 配方，但底层构建生命周期仍通过 =zeta_forge.cmake_builder.CMakeProjectBuilder= 执行。

#+begin_src bash
cd "$ZETAX_ROOT/zpp"
./zbuild.py --rebuild --no-tests
#+end_src

该入口默认把当前 =zpp= checkout 作为 =ZETA_ZPP_SRC_DIR=，除非用户显式设置了这个变量。
它会通过 =$ZETAX_ROOT/zeta_forge= 或附近兄弟目录复用共享编译工具库，zpp 特有构建逻辑位于 =zpp/builder/=。

* 当前说明

- gRPC 是工作区内核心 RPC 依赖族的统一来源：Abseil、Protobuf、zlib、TLS/BoringSSL、c-ares、RE2、upb、utf8_range、xxhash 和 address_sorting。
- gRPC 的测试/工具生态依赖，例如 benchmark、bloaty、googletest、googleapis、xDS、Envoy API、protoc-gen-validate 和 OpenTelemetry C++，默认不作为 Zeta Forge 开发依赖安装。
- 外部 zpp 构建默认使用 =3rd/taskflow= 和 =3rd/rapidjson=。
- RapidJSON 通过 =RAPIDJSON_ROOT= 传递给 zpp。
- zpp 的 HPX examples 仍依赖系统中已安装的 HPX；如果该 HPX 安装缺少可发现的 Asio，配置 HPX examples 时可能失败，此时需要补齐 Asio 或重新构建 HPX。
