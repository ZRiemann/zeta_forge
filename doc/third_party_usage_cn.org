* 第三方系统使用 zeta_forge 工具链说明

本文说明外部项目如何复用 =zeta_forge= 的通用 C++ 编译工具链。架构背景见 [[file:architecture_cn.org][architecture_cn.org]]。

* 前置条件

建议目录布局：

#+begin_src text
$ZETAX_ROOT/
  zsa/
  zeta_forge/
  your_project/
#+end_src

加载 =zsa= 环境后，=ZETAX_ROOT= 会指向顶层工作区。也可以不依赖 =zsa=，直接手动设置 =ZETAX_ROOT=：

#+begin_src bash
export ZETAX_ROOT=/path/to/workspace
export ZETA_INSTALL_PREFIX=$HOME/.local
#+end_src

首次使用前，建议准备 zeta_forge 工具链：

#+begin_src bash
cd "$ZETAX_ROOT/zeta_forge"
./common/prepare_debian.sh
./zbuild.py grpc --rebuild --install
./zbuild.py hpx --rebuild --install
./zbuild.py folly --rebuild --install
./zbuild.py nng --rebuild --install
#+end_src

* 关键环境变量

- =ZETAX_ROOT=：ZetaX 顶层工作区根目录，例如 =~/git=。
- =ZETA_INSTALL_PREFIX=：依赖安装前缀，默认 =~/.local=。
- =ZETA_3RD_DIR=：第三方源码根目录，默认 =$ZETAX_ROOT/zeta_forge/3rd=。
- =ZETA_<NAME>_SRC_DIR=：覆盖某个源码目录，例如 =ZETA_GRPC_SRC_DIR=、=ZETA_TASKFLOW_SRC_DIR=。项目也可以定义自己的源码变量，例如 zpp 使用 =ZETA_ZPP_SRC_DIR=。

外部项目不需要额外引入 forge 专用根变量；公共路径契约统一为 =$ZETAX_ROOT/zeta_forge=。

* 最小项目入口

外部项目可以在自己的仓库根目录放一个薄 =zbuild.py=：

#+begin_src python
#!/usr/bin/env python3
from __future__ import annotations

import os
from pathlib import Path
import sys


def is_forge_root(candidate: Path) -> bool:
    return (candidate / "common" / "zeta_forge" / "config.py").is_file()


def find_forge_root() -> Path:
    candidates: list[Path] = []
    if os.environ.get("ZETAX_ROOT"):
        candidates.append(Path(os.environ["ZETAX_ROOT"]).expanduser() / "zeta_forge")
    candidates.extend(parent / "zeta_forge" for parent in PROJECT_ROOT.parents)
    for candidate in candidates:
        if is_forge_root(candidate):
            return candidate.resolve()
    raise RuntimeError("Set ZETAX_ROOT=/path/to/workspace and ensure $ZETAX_ROOT/zeta_forge exists")


PROJECT_ROOT = Path(__file__).resolve().parent
FORGE_ROOT = find_forge_root()
sys.path.insert(0, str(FORGE_ROOT / "common"))

from builder.your_project import main


if __name__ == "__main__":
    raise SystemExit(main(PROJECT_ROOT))
#+end_src

这个入口只做三件事：定位 =zeta_forge=、导入公共工具库、把当前项目根目录传给项目构建逻辑。

* 复用 CMakeProjectBuilder

项目构建逻辑可以继承 =CMakeProjectBuilder=：

#+begin_src python
from pathlib import Path

from zeta_forge.cmake_builder import CMakeProjectBuilder, CommonBuildArgs, common_build_argument_parser
from zeta_forge.config import load_repo_config


class YourProjectBuilder(CMakeProjectBuilder):
    @property
    def project_name(self) -> str:
        return "your_project"

    @property
    def source_dir(self) -> Path:
        return Path(self.repo_config.env["YOUR_PROJECT_SRC_DIR"]).resolve()

    @property
    def missing_source_hint(self) -> str:
        return "Set YOUR_PROJECT_SRC_DIR or run from the project checkout"

    def conan_install_command(self) -> list[object]:
        return [
            "conan",
            "install",
            self.script_dir / "conanfile.py",
            f"--output-folder={self.conan_root}",
            "--build=missing",
            "-s",
            f"build_type={self.args.build_type}",
            "-c",
            "tools.cmake.cmaketoolchain:generator=Ninja",
        ]

    def configure_command(self) -> list[object]:
        return [
            "cmake",
            "-S",
            self.source_dir,
            "-B",
            self.build_dir,
            "-G",
            "Ninja",
            f"-DCMAKE_BUILD_TYPE={self.args.build_type}",
            f"-DCMAKE_TOOLCHAIN_FILE={self.conan_toolchain_file}",
            f"-DCMAKE_PREFIX_PATH={self.repo_config.install_prefix}",
            f"-DCMAKE_INSTALL_PREFIX={self.repo_config.install_prefix}",
            f"-DCMAKE_CXX_STANDARD={self.repo_config.cxx_standard}",
        ]
#+end_src

如果项目不使用 Conan，可以设置 =uses_conan = False=，并让 =configure_command= 直接使用系统或 forge 安装前缀中的依赖。

* 复用依赖配方

外部项目有三种依赖管理方式：

1. 直接依赖 =ZETA_INSTALL_PREFIX= 中已安装的 gRPC、HPX、Folly、NNG 等库。
2. 在项目自己的 =builder/conanfile.py= 中声明项目私有依赖，同时通过 =CMAKE_PREFIX_PATH= 引入 forge 安装前缀。
3. 如果某个依赖组合会被多个项目共享，优先抽象为 zeta_forge 公共库能力；项目目标本身仍留在项目仓库。

优先选择第一种或第二种；只有共享价值明确的公共流程才放回 =zeta_forge=。

* zpp 接入范式

=zpp= 是外部项目复用 zeta_forge 的参考结构：

#+begin_src text
$ZETAX_ROOT/zpp/
  zbuild.py
  builder/
    __init__.py
    zpp.py
    conanfile.py
#+end_src

=zbuild.py= 负责通过 =$ZETAX_ROOT/zeta_forge= 或附近兄弟目录定位 =zeta_forge= 公共库；=builder/zpp.py= 定义 =ZppBuilder=，继承 =CMakeProjectBuilder= 并注入 zpp 特有的 Conan 参数、CMake 选项和测试/示例开关。

* 常见命令

使用 forge 内置目标：

#+begin_src bash
cd "$ZETAX_ROOT/zeta_forge"
./zbuild.py list
./zbuild.py all --rebuild --install
#+end_src

在外部项目中使用自己的入口：

#+begin_src bash
cd "$ZETAX_ROOT/your_project"
./zbuild.py --BUILD_TYPE=Debug
./zbuild.py --rebuild --install
#+end_src

覆盖源码或安装前缀：

#+begin_src bash
export ZETA_INSTALL_PREFIX=$HOME/.local/zeta
export ZETA_TASKFLOW_SRC_DIR=$HOME/git/taskflow
./zbuild.py --rebuild
#+end_src

* 故障排查

- 找不到 =zeta_forge=：确认 =ZETAX_ROOT=/path/to/workspace= 已设置，并且 =$ZETAX_ROOT/zeta_forge= 存在；未设置 =ZETAX_ROOT= 时，确认外部项目与 =zeta_forge= 是标准兄弟目录布局。
- 找不到依赖包：确认基础目标已经用 =--install= 安装到 =ZETA_INSTALL_PREFIX=，并检查 =CMAKE_PREFIX_PATH=。
- Conan toolchain 不存在：重新运行项目入口并加 =--rebuild=，或删除对应 =build/<BUILD_TYPE>/conan= 后重试。
- 源码路径不对：检查 =ZETA_<NAME>_SRC_DIR= 是否覆盖到了预期 checkout。
- 构建目录搬迁后 CMake 报错：使用 =--rebuild= 清理当前 build type 的 CMake 状态。

* 版本与更新

外部系统依赖 =zeta_forge= 公共行为时，应记录所使用的 =zeta_forge= 版本。当前版本在 [[file:../VERSION][../VERSION]]，更新说明在 [[file:../CHANGELOG.org][../CHANGELOG.org]]。

当外部项目依赖公共 CLI、环境变量、Conan 配方或 Builder API 时，升级 =zeta_forge= 前应先阅读对应版本的更新说明。
