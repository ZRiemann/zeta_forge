* 范围

这是 2026-09-22 的历史记录；当前用法见 [[file:build.org][构建契约]]。
本次迁移和翻译没有重新执行记录中的验证。

本文是工作区实现记录，不代表发布或全平台验收。当时未创建版本、标签或提交。
保留了 practice 已有的 manifest/规划修改及 agent 未跟踪的 .vorg.db。
未修改第三方源码、依赖 lockfile 或已有不可变 Rust 基线。
Cat 新增的 1.97.1-r2 基线记录其已有 lockfile 中的直接依赖。

对全部七个可构建仓库的入口执行了 help、list、build/test dry-run、profile 选择，
以及拒绝已移除参数的验证。额外共享测试覆盖选择、不支持的能力、执行前预检、
失败/中断、参数脱敏、CMake component、Cargo/Dioxus feature、profile 清理
（包括 Dioxus server/wasm 缓存）和 Android APK 保留。

* 复现

在表中对应仓库执行：

#+begin_src sh
# Forge
python3 -m unittest discover -s tests
# Trader
python3 -m unittest discover -s tests/python
# Practice
./zbuild.py check --profile debug -j 2
./zbuild.py test --profile debug -j 2
./zbuild.py build --profile release -j 2
# Agent / Vault / zpp: select the profile shown in the table
./zbuild.py test --profile debug -j 2
# Cat
./zbuild.py test server --profile debug -j 2
python3 ops/test_build_calls.py
# zsa
python3 agents/check_agents.py
python3 deploy/zeta_cat/test_build_calls.py
#+end_src

这些结果不能证明每个交付物或平台都通过。
zpp 日志测试失败是当时观察到的问题，并未在该次构建入口改造中修复。
缺少的原生 package 必须显式准备；构建不会通过安装宿主机软件绕过验证失败。
