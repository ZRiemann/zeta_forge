* 统一构建契约

=./zbuild.py <command> [deliverable ...] [--profile release|debug]= 默认使用 release，
按 =deps grpc hpx folly nng= 顺序执行。显式指定名称可缩小交付范围。
=list= 显示支持的动作；=metadata= 描述原生工程单元及产物；=--dry-run= 无需工具、
签名材料或服务即可预览执行范围。旧的 flag-only、stack-first 和别名语法无效。

=build= 构建并将依赖包物化到项目内的 =build/staging/<profile>/<target>/=。
只有 staging 完成后才记录成功，绝不发布到 =ZETA_INSTALL_PREFIX=。
Folly 配置前会先暂存其所需的 gRPC package。=install= 要求显式指定目标名称，
且同一 profile 已成功构建；只发布这些目标，不重新构建或运行 Conan。
未显式选择安装的构建前置依赖只保留在 staging 中。
CMake 和 pkg-config 元数据会调整为发布前缀。=install deps= 随 CMake 包文件一起
发布 OpenSSL manifest。如果 staging 缺少该文件，请重新构建 =deps=。
Forge 在发布前核验暂存产物清单及其外部引用。只有旧完成标记的目标需要重新构建一次。
原构建目录移除后，仍可从 stage 发布。Forge 在 =<prefix>/share/zeta_forge/native/=
记录文件归属并恢复中断的发布。旧安装文件冲突时，首次安装请使用新前缀。
发布 Folly 需要先发布或同时发布与其构建记录匹配的 gRPC。
发布 HPX 时会从安装后的 CMake 配置中去除 HPX 和随包安装的 Stdexec 的构建目录设置。
=clean/rebuild= 仅影响一个 profile 下指定的原生构建目录及目标 staging，
不影响安装内容或共享 Conan/Cargo 缓存。=rebuild= 随后重建所选产物及必要依赖。

原生构建的 =-j= 并行度同时适用于 CMake 和 Conan 包构建。
原生依赖策略由 =common/zeta_forge/conan_policy.py= 管理。Forge 为 deps、HPX
和 Folly 一同生成配方与策略快照，请通过 =zbuild.py= 准备。
这些目标将 Conan 锁文件和解析记录保留在 =build/conan-state/<目标>/<profile>/=。
=rebuild= 保留锁文件，并用它重新生成缺失或变更的输出。可在 =build=、=check=
或 =rebuild= 中使用 =--refresh-conan-lock=，为选定的 Conan 目标重新解析锁文件。
=--dry-run= 只显示刷新范围。

对于 Boost 1.91.0，=deps=、=hpx= 和 =folly= 使用基于固定 Conan Center 修订版的
Forge 配方。Forge 在解析依赖前将补丁后的配方导出到本机 Conan 缓存。
Boost.Cobalt TLS 使用 =ZETA_OPENSSL_VERSION= 选定的 Conan OpenSSL（默认 =3.6.2=）。
生成的 =Boost::cobalt_io_ssl= 目标传递 Cobalt I/O 和 OpenSSL 链接依赖。
=ZETA_BOOST_VERSION= 选用其他版本时使用对应的上游配方。

Forge 将 Conan 的 Libevent 库和头文件路径直接传给 Folly 的查找模块，
避开 CMake 4 中已移除的 CMP0026 旧行为。清理后重建仍使用同一配置。

Forge =check= 配置并编译所选原生库。显式 =doctor rust-deps= 离线静态审计，
=check rust-deps= 另外完整执行固定工具链的 =--locked --offline= 解析，不编译。
=check rust-updates= 读取当前锁定图后显式查询 crates.io/GitHub 升级候选，不采用更新；
其 metadata/list/help/dry-run 只描述范围且不联网。报告及失败语义见
[[file:rust_workspace.org][Rust 治理说明]]。=test= 默认选择 =build-tools=，运行 Python 工具测试，
而非上游第三方测试套件。默认使用 Forge 自有 fixture 覆盖公共入口及共享适配器，
无需同级仓库或网络。显式运行 =python3 tests/manual/cmake_consumers.py= 可检查真实
同级 CMake 入口。该命令报告可用仓库的 revision，前置条件缺失或兼容性检查失败时
返回非零状态。Phase 3 的兼容契约清单见[[file:../../BUILD.org::*Phase 3 compatibility baseline][英文构建契约]]。
不支持的上游测试、运行及 fetch 能力会报错。
宿主机准备仍使用 =common/prepare_debian.sh=，不属于构建动作。
构建不会覆盖全局 Conan profile；应单独准备所选 Conan profile。

#+begin_src sh
./zbuild.py list
./zbuild.py build nng --profile debug
./zbuild.py rebuild nng --dry-run
./zbuild.py build deps nng
./zbuild.py install deps nng
./zbuild.py test
#+end_src

公共契约位于 =common/zeta_forge/build_cli.py=；原生适配器为
=cmake_engine.py=、=rust_engine.py=、=gradle_engine.py=；项目定义位于
=builder/project.py= 和 =builder/<target>/project.py=。
应用保留自己的薄入口与项目定义，不建立 subsystem 注册或另一套原生依赖图。
根目录 =zbuild.py= 是唯一可执行的 Forge 构建入口。
