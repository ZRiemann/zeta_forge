* 源码与依赖基线

HPX 由 =3rd/hpx= submodule 管理。2026-10-15 的升级将上游 =master= 从
=41bf79c56fc9df3190efbf146e6cbd444fa3b6b0= 快进到
=6e97afa18a1a189d0147397ecb3400917aef2b94=，不添加上游源码补丁。
源码版本号为 =2.0.0=，这是固定的开发快照，不是正式发布 tag。

HPX Builder 同步固定 stdexec 为该上游快照采用的
=04de75de5807e73a229acf047c6976575e313359=。二者必须配套升级：如果保留
Forge 原来的覆盖配置，即使更新 HPX，仍会选中旧 stdexec。
保留 C++20、静态链接、jemalloc、networking 和 MPI parcelport；
上游 examples/tests 继续关闭，tools 继续开启。

源码覆盖变量 =ZETA_HPX_SRC_DIR= / =ZETA_3RD_DIR= 必须指向预期 checkout。
安装前缀沿用 =ZETA_INSTALL_PREFIX=，默认 =~/.local=。
不修改代理环境、应用 JSON 或 HPX INI 配置。

* 消费端兼容性

HPX 保留 =as_sender=、=make_future= 和 =thread_pool_scheduler=。
Future sender 的内部实现和完成环境发生变化；=make_future= 从 tag-invoke
定制改为直接重载与 scheduler query。zpp 继续提供原有 =from_future=、
=into_future= 和 scheduler 接口。

zpp 的 =HPX_GIT_COMMIT= 检查用于确认源码与安装库来源一致，不代表 API
兼容检查。配置 zpp 前先构建、安装 HPX，再安装 =zpp_hpx=，使导出的 package
记录相同版本。静态链接消费者需要重新构建，旧二进制不能作为升级验收证据。
单 worker 协作等待回归使用携带 scheduler 的 Future 转换，避免阻塞 OS worker。

Forge 从 =git rev-parse HEAD= 显式传入 =HPX_WITH_GIT_COMMIT= 及其短格式。
上游带路径过滤的 =git log= 可能跳过 merge commit 而记录父提交，造成 zpp
精确版本检查误拒绝。显式传入还会使源码提交变化反映到 configure 参数中，
即使受监测的 CMake 文件没有变化，也会重新配置。

* Release 交付与验证

逐步执行，每一步成功后再继续。已安装的共享 Release 依赖是前置条件。
Forge 的 =build= 先完成项目内 staging；=install= 只发布选定的成功构建，不重复编译。

#+begin_src bash
cd "$ZETAX_ROOT/zeta_forge"
./zbuild.py test
./zbuild.py doctor hpx --profile release
./zbuild.py build hpx --profile release --jobs 4
./zbuild.py install hpx --profile release

cd "$ZETAX_ROOT/zpp"
./zbuild.py test zpp_hpx --profile release --jobs 4
./zbuild.py build example_hpx_basic zpp_hpx_basic zpp_hpx_exec_pipeline zpp_hpx_exec_scheduler --profile release --jobs 4
./zbuild.py run zpp_hpx_exec_pipeline --profile release
./zbuild.py run zpp_hpx_exec_scheduler --profile release
./zbuild.py install zpp_hpx --profile release --jobs 4

cd "$ZETAX_ROOT/zeta_trader"
./zbuild.py build zeta_trader_hpx --profile release --jobs 4
./zbuild.py test zeta_trader_hpx --profile release --jobs 4
#+end_src

zpp 入口运行配置的 core 和 HPX CTest 正确性套件。execution 回归覆盖
shared_future 复用、值/void/移动专用值、异常、带 scheduler 的未完成 Future
及 sender-to-future 转换。runtime 测试分别使用双 worker 和单 worker，
每个用例设置 15 秒超时。Trader 测试入口运行其配置的共享正确性套件，
范围大于选定的服务目标，不启动生产服务栈。

另用临时独立 CMake 消费者验证 =find_package(zpp_hpx CONFIG REQUIRED)=
和 =zpp::hpx=；确认错误的 HPX 预期提交会被拒绝，并核对源码、安装的 HPX
和 zpp 导出记录的 commit 一致，stdexec checkout 与 Builder 固定版本一致。

以上是验收流程，不代表命令已经执行通过，实际结果需单独记录。
Debug、sanitizer、性能/RSS 基准、长时间压力测试和真实 Provider/HPX 联调
不在本次 Release 验收范围。此次 HPX 升级不需要交易连接、生产重启或前端重建。
