* 目标与文档权威

设计日期为 2026-11-12。本文描述待实施方案，不代表功能已经实现。
用户已同意制定统一设计，后续由其他 agent 按 Stage 实现。
[[file:../project_progress.org][进度台账]]是状态、验证证据和实际交付版本的唯一记录。
英文设计为主文档，本文同步维护契约与阶段范围，不另建状态表。

Phase 2 负责 Forge 原生依赖的解析、构建计划、暂存和发布。
既有 Phase 1 Rust 治理编号保持不变。当前 [[file:../../BUILD.org][BUILD.org]] 优先于通用技能默认值，
尤其保留 install 仅发布、不隐式构建的行为。

目标是明确包内文件归属、完整交付、可解释的缓存复用、可重复的依赖解析和可恢复的发布。
保留薄 zbuild.py、共享 Engine 协议以及 CMake/Cargo 原生依赖图。

范围不包括业务仓库修改，Rust/Gradle/Zig 引擎重写，上游源码修改，清理全局缓存，
自动升级依赖，部署远程二进制缓存，通用插件框架及可移植 SDK 打包。
现有 Conan 配置会引用本机缓存，RapidJSON 配置可能引用源码目录。
本阶段记录并校验这些外部引用，不把现有安装宣称为独立可搬迁的 SDK。

Boost 是用户实际遇到的打包失败；其余生命周期和恢复问题属于静态发现或风险。
本次设计没有运行全量编译。配方导出、依赖图解析、B2 dry-run 均不能证明实际安装和链接正确。

* 保留的公开行为

- 保留动作名称、release/debug 映射、默认目标、退出码 0/1/2/130 及 ZETA_BUILD_DONE。
  现有汇总计数保持引擎步骤语义；新增目标级日志不能悄悄改变计数含义。
- help/list/metadata/dry-run 不导出配方、不创建锁文件、不写构建状态、不要求工具已安装。
  doctor 只读检查，缺失状态直接报告。
- build/check 保留当前 Forge 原生目标行为，包括本地暂存。
  install 要求显式目标，不编译、不解析 Conan，也不自动发布未选中的前置依赖。
  缺失已安装前置依赖时给出明确错误。
- rebuild 只清理选中目标和 profile 的构建、暂存目录；前置依赖可增量构建。
  clean/rebuild 保留安装目录、其他 profile、共享 Conan 缓存及依赖解析锁状态。
- 保留 ZETA_* 配置和代理继承。日志与清单不保存完整环境、凭据或代理密钥。
- 受管 Boost 配置继续启用 Cobalt TLS，维持 Boost::cobalt_io_ssl 与 OpenSSL 依赖元数据。
  本阶段保留公开 openssl-native.json schema 1 和既有 Release 读取契约。
  内部产物记录使用独立 schema，不借重构改变 Rust 使用方契约。

* 模块职责与依赖方向

#+begin_example
zbuild.py -> build_cli -> ForgeEngine / 不可变 NativePlan
                            |-- ConanSession -> Conan 与受管配方准备
                            |-- 现有 Builder -> CMake/Ninja
                            |-- ArtifactSet 校验 -> Publisher
策略与记录类型不反向依赖 ForgeEngine 或具体 Builder。
Conan 管理包依赖图，CMake 管理编译依赖图。
#+end_example

下表是建议模块与接口边界，不要求机械增加同名类，不引入通用服务容器，暂不作为外部稳定 API。

| 所有者与建议位置 | 负责的契约和状态 |
|------------------+------------------|
| builder/project.py 与 builder/native_plan.py | TargetSpec 和纯计划生成；选择范围、前置顺序、清理与发布范围 |
| common/zeta_forge/conan_policy.py | 唯一版本与选项基线，解析受支持 ZETA 覆盖项，显式记录使用方差异 |
| common/zeta_forge/conan_session.py | ConanInputs 到 ResolvedConan；命令、profile 身份、指纹、锁与解析记录 |
| common/zeta_forge/conan_boost.py 与 builder/boost/ | 返回精确配方引用和补丁身份，包专属校验，不继承通用 CMake Builder |
| 现有 builder/<target>/project.py | 目标专属 CMake 参数、原生构建与候选暂存适配 |
| common/zeta_forge/native_artifacts.py | 产物清单、构建记录、摘要、外部引用与重定位规则 |
| common/zeta_forge/native_publish.py | 安装前缀文件归属、冲突、事务日志、恢复及安装记录 |
| 现有 build_ops.py/process.py | 文件系统与进程操作，不承载 Boost 或依赖版本策略 |

config.py 继续负责环境和路径。依赖默认值迁到唯一策略所有者，临时兼容导出只委托这一来源。
Conan 配方必须在独立导出环境中取得同一策略，不依赖碰巧存在的 Python 搜索路径。
Stage 2.2 使用显式导出的策略快照。Forge 将原生消费配方与 =native-policy.json=
一同准备，缺少快照时明确报错。受管 Boost 导出通过 =forge-openssl-version.txt=
绑定 OpenSSL 版本。
影响配方行为的策略必须进入配方身份或显式 Conan settings/options，不能仅通过隐藏环境变量
在同一身份下选择不兼容行为。

TargetSpec 只声明交付目标关系，初始为 folly -> grpc；不复制原生包或编译图。
describe/preflight/execute 使用同一纯函数生成的计划，可在单次请求中缓存。
保持外部项目使用的 Engine 协议。

* 数据与缓存契约

| 数据及 schema | 必需内容 |
|---------------+----------|
| NativePlan，内部类型 | action、profile、显式目标、前置顺序、构建/清理/发布范围、路径、jobs；不可变且确定 |
| ConanInputs，内部类型 | schema、目标、host/build profile 身份及有效 settings/options/conf、版本策略、配方与导出输入摘要、工具链输入、Conan/编译器/生成器身份 |
| ResolvedConan，schema 1 | 输入指纹、精确配方及 revision、依赖图身份、package ID 与可获得的 package revision、锁摘要、生成文件清单、工具身份 |
| ArtifactSet，内部类型 | target/profile 所有者、输入与依赖身份、相对文件路径、类型/权限/摘要或符号链接目标、外部引用、重定位规则 |
| BuildReceipt，schema 1 | 产物清单、成功构建来源、配方与锁身份、源码 revision 与脏状态标识、完成 ID；最后写入 |
| InstalledReceipt，schema 1 | 来源构建记录摘要、前缀、重定位后文件摘要、依赖身份、所有者集合、发布事务 ID |

未知 schema 拒绝并提示重建或重新发布。路径不得逃逸所属根目录；拒绝路径穿越及逃逸链接。
支持原生安装所需的安全相对符号链接，不能直接全部解引用。
JSON 使用规范化序列化，时间戳只用于诊断，不作为缓存身份。

按内容计算配方、profile include、用户工具链与声明配置文件闭包的摘要，包含新增、删除文件。
C++ 标准、FMT、编译器、profile 或补丁内容变化须使相关 Conan 生成失效；保留旧 mtime 不能隐藏变化。
源码 revision/脏状态属于构建来源；除非 Conan 配方真正使用该源码，否则不因此重新解析 Conan。
增量编译仍由 CMake/Ninja 管理。

jobs 和传输凭据不改变产物身份，但 jobs 必须传到 Conan 包编译和 CMake，并继续继承代理。
最终发布前缀变化不触发依赖重编译；生成目录、构建位置变化可能需要重新生成。

本地锁与解析记录放在 build/conan-state/<target>/<profile>/<input-fingerprint>/，
位于单目标 clean 范围之外。各代解析记录不可变，成功指针最后写入。
生成文件缺失或损坏时，使用已有锁重新生成，不自动升级。
Conan 自己管理源码与二进制缓存；相同包身份复用，不同配方 revision 或 options 可合法触发新工作。
不得复制 Conan 缓存目录来伪造跨身份复用。

新输入指纹允许在 build/check/rebuild 中先解析并持久化锁，再编译；相同输入后续复用锁。
新增 Forge 专属 --refresh-conan-lock，仅允许这三个动作；install/doctor 等动作拒绝该参数。
预览只展示意图，不操作工具或网络。刷新生成候选图，报告变化，成功解析后才替换活动锁。
普通 rebuild 不刷新锁。这是本 Phase 唯一计划新增的公开 CLI 参数。

保留可导出的、去除敏感信息的解析包，包含 Conan lock、有效 profiles/settings/options 和配方身份。
不假设锁文件包含全部二进制输入，也不保证远端永久保留 revision。
本地锁用于重复构建，跨主机复现需要批准的基线解析包。
Stage 2.3 必须核对实际 Conan 2 的 JSON、锁语义及受支持命令，用 fixture 和工具验证覆盖范围。

不强行让 deps/hpx/folly 共享一个依赖图或 package ID。
Folly 当前关闭 Boost zlib，deps 未关闭；这些差异先保留为有说明的覆盖项。
比较重叠且影响 ABI 的依赖，拒绝不兼容发布组合；约束从实际导出链接接口推导，
不能把所有可选构建差异都当作 ABI 不兼容。

* 包、暂存与发布生命周期

** Boost 文件归属修复

继续使用固定上游配方及 Forge 补丁。先以最小 B2 fixture 重现安装复制依赖的行为。
优先验证能否在维持链接和使用要求的同时阻止外部预编译目标安装。
若不可行，在 recipe package 阶段依据实际依赖清单与内容一致性，过滤被证明是外部
ssl/crypto/z 副本的文件。意外文件或内容不符必须失败。
禁止放宽 non_used、禁用 Cobalt 或无差别删除非 Boost 文件。
Stage 2.1 验收前记录采用的机制和证据。

** 暂存和构建记录

流程固定为构建、候选暂存、校验、切换暂存、最后写成功记录。
每次生成干净候选目录，不向旧暂存目录叠加文件。
各目标先用小 fixture 证明 install-prefix/DESTDIR 的实际行为，不假设上游具有相同重定位能力。
保留公开 build/staging/<profile>/<target>/ 路径。
当前构建失败后，保留的旧文件不能被误认为本次成功产物；切换中断且记录不匹配时禁止发布，
后续构建可以重建该目标暂存。

deps 清单包含全部预期 CMake 配置、兼容配置和 openssl-native.json。
按文件角色排除脚本及敏感文件，不再用单一后缀决定全部交付内容。
OpenSSL JSON 必须指向 CMake 依赖图使用的同一份已验证 Conan 包。

install 校验已记录快照及当前文件内容，不要求源码树仍与构建时完全相同。
它发布明确记录的成功构建；源码修改本身不隐式触发构建。
产物缺失、被篡改、外部缓存引用消失或请求 profile 不匹配时失败。
日志展示构建身份，避免用户不清楚安装的是哪次产物。

** 发布和所有权

install 从暂存产物发布，不再从可变构建目录重新运行 CMake install。
修改公开文件之前，预检所有选中清单及目标路径冲突。
候选发布文件、备份放在最终前缀所在文件系统的 Forge 事务目录中。

构建/暂存使用 target/profile 锁，Forge 发布使用前缀级写锁。
统一先按确定顺序取得目标锁，再取得前缀锁，不反向获取。
install 在安全复制所需产物快照前持有源暂存锁。
使用进程退出可释放的操作系统锁，配合日志识别中断事务；doctor/metadata 不改锁状态。

前缀归属记录位于 <prefix>/share/zeta_forge/native/。
相同内容可具有多个明确所有者，移除一个所有者不删除其他所有者仍使用的文件。
与未选中目标的内容冲突在写入前失败。不同 profile 共用相同安装路径也视为不同所有者，
内容不同时不能悄悄覆盖。仅当文件已无其他所有者且当前摘要匹配旧记录时，删除本次淘汰文件。
保留无关文件。

旧安装没有归属记录时，可明确接管字节一致的文件；已有且内容不同的文件保留，报告路径和摘要冲突。
不能自动接管整个 ~/.local。首次迁移验收建议使用新前缀；清理冲突旧文件需用户另行授权。
旧 target/profile 成功标记需要一次普通 build 生成新记录，不要求清理 Conan 缓存。

发布前在候选区处理 .cmake/.pc 元数据。
重定位映射覆盖本目标及声明的前置依赖；未选中前置依赖必须已安装且身份兼容，否则报告显式安装要求。
拒绝残留 Forge build/staging 路径，允许清单声明的 Conan 缓存和源码引用。
不对二进制数据或任意路径进行盲目替换；验证代表性 imported target。

一次 install 请求的选中目标构成一个带日志的事务。
备份将替换或删除的受管文件，逐文件原子替换，最后提交安装记录。
普通失败回滚文件与记录；下一次修改型 install 在前缀锁保护下先恢复中断事务。
无法恢复时保留日志并失败，不清理证据或宣称成功。
定义日志和备份的持久化顺序，并注入崩溃点测试。
此机制保证可恢复，不保证整个前缀对外部并发读取者原子可见；运行中部署及非 Forge 写入者需要另行协调。

** 整体验收命令

在 Forge 工作区使用正常的 Conan profile 和源码 checkout 执行。
以下命令发布到 =build= 下的新前缀，请保留验收目录和日志以对应本次测试的改动。

运行 =bash tests/manual/native_delivery/acceptance.sh= 可用
[[file:../../tests/manual/native_delivery/acceptance.sh][验收脚本]] 执行整套流程并逐步记录日志。
加上 =--rebuild-release= 会先清理本次选定的 Release 构建和暂存目录，再进行构建。

#+begin_src bash
(
  set -euo pipefail
  mkdir -p build
  evidence=$(mktemp -d "$PWD/build/phase2-acceptance.XXXXXX")
  export ZETA_INSTALL_PREFIX="$evidence/release-prefix"
  git rev-parse HEAD > "$evidence/head"
  git diff HEAD --binary | sha256sum > "$evidence/worktree.sha256"
  conan --version
  cmake --version
  ./zbuild.py build deps grpc hpx folly nng --profile release -j 4 |& tee "$evidence/build.log"
  ./zbuild.py build deps --profile release -j 2 |& tee "$evidence/reuse.log"
  ./zbuild.py rebuild deps --profile release -j 4 |& tee "$evidence/rebuild.log"
  ./zbuild.py install deps grpc hpx folly nng --profile release |& tee "$evidence/install.log"

  cmake -S tests/manual/native_delivery -B "$evidence/consumers" -G Ninja \
    -DCMAKE_BUILD_TYPE=Release \
    "-DCMAKE_PREFIX_PATH=$ZETA_INSTALL_PREFIX;$ZETA_INSTALL_PREFIX/lib/cmake/zeta_deps/Release"
  cmake --build "$evidence/consumers" --parallel 4 --verbose |& tee "$evidence/consumers.log"
  ctest --test-dir "$evidence/consumers" --output-on-failure | tee "$evidence/ctest.log"
  python3 tests/manual/native_delivery/rust_smoke.py "$ZETA_INSTALL_PREFIX" \
    "$evidence/rust-openssl" |& tee "$evidence/rust.log"

  sha256sum "$ZETA_INSTALL_PREFIX/lib/libnng.a" > "$evidence/release-nng.sha256"
  ./zbuild.py build nng --profile debug -j 4
  ZETA_INSTALL_PREFIX="$evidence/debug-prefix" ./zbuild.py install nng --profile debug
  ./zbuild.py clean nng --profile debug
  sha256sum -c "$evidence/release-nng.sha256"
  test -f build/staging/release/nng/.zeta-build-complete.json
  printf 'Acceptance evidence: %s\n' "$evidence"
)
#+end_src

Release 的 NNG 归档保持原样。检查 Conan 日志中的 jobs 变更复用和 rebuild 保留锁记录。
随日志保留构建记录与安装归属索引。输入变化、事务恢复和旧安装冲突由聚焦测试覆盖。

* Agent 交接规则

开始时读取台账、本文、BUILD.org、当地指引和当前 diff，保留其他人的工作。
按前置关系选择一个 Stage，编辑前声明负责文件。多个 agent 共享工作区时不得覆盖或回退其他改动。
builder/project.py、config.py 和共享适配器由单一集成负责人协调，不能未经分工同时编辑。
可在契约确定后独立准备 fixture，集成仍按前置关系进行。

完成时更新台账的实现范围、实际检查、未运行门槛、未决事项和下一步。
改变 schema、所有权或 CLI 决策时同步中英文设计。
3rd 源码保持原样，补丁资产放在 builder/boost。全量编译交给用户。
取得对应打包和使用方验证前，不宣称先前 Boost 故障已经解决。
