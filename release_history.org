#+TITLE: Zeta Forge Release History

* Release History

** v0.6.1 - 2026-07-31
*** 发布定位摘要
- 统一仓库 C/C++ 格式化规则，并固定 HPX 使用的 stdexec 源码版本。
- 补充 zpp 可选 HPX 模块的依赖兼容约束，zeta_forge 从 =v0.6.0= 升级到 =v0.6.1=。

*** 变更内容
- 新增根目录 =.clang-format=，并通过 =.clang-format-ignore= 排除 =3rd/**= 第三方源码。
- Git 忽略规则新增本地 =.vorg.db= 与 =.vscode/= 工作区文件。
- HPX Builder 启用 =HPX_WITH_FETCH_STDEXEC=，并将 =HPX_WITH_STDEXEC_TAG= 固定为 commit =05e3f5ec59655fee2536fc3116e5ffb4927ae955=。
- 更新中英文 README，说明 HPX stdexec 的固定版本，以及 zpp 可选 HPX 模块对已安装 HPX、forge Asio/Hwloc 兼容配置和 =HPX_GIT_COMMIT= 一致性的要求。

*** 兼容性与升级说明
- 构建 HPX 时需要能够获取固定 commit 的 stdexec 源码；离线构建环境应提前准备对应源码缓存。
- zpp 可选 HPX 模块要求已安装 HPX 的 =HPX_GIT_COMMIT= 与当前 =3rd/hpx= 源码一致，不匹配的安装需要重新构建。
- 仓库格式化不处理 =3rd/**=，避免改写托管的第三方源码。

** v0.6.0 - 2026-07-31
*** 发布定位摘要
- 为共享 Conan 依赖环境增加 SQLite3 支持。
- 按公共依赖能力升级，zeta_forge 从 =v0.5.0= 升级到 =v0.6.0=。

*** 变更内容
- =common/zeta_forge/config.py= 新增 =ZETA_SQLITE_VERSION=，默认值为 =3.53.3=。
- =builder/deps/conanfile.py= 新增 =sqlite3/{SQLITE_VERSION}= 依赖，并设置 =sqlite3/*:shared=False=，默认生成静态 SQLite3 package config。
- 更新中英文 README，明确 =zeta_forge deps= 统一管理 =SQLite3= 等共享 Conan 依赖版本。

*** 兼容性与升级说明
- 需要 SQLite3 的外部项目应先运行 =./zbuild.py deps --BUILD_TYPE=<type> --install=，再通过安装前缀下的 =zeta_deps/<BUILD_TYPE>= package config 消费 =SQLite3=。
- 如需临时切换 SQLite3 版本，可在运行 =deps= 目标前设置 =ZETA_SQLITE_VERSION=。

** v0.5.0 - 2026-07-05
*** 发布定位摘要
- 更新核心第三方源码版本，并收紧 Folly 与 HPX 的可安装库构建路径。
- 改进公共 CMake Builder 的编译数据库入口，zeta_forge 从 =v0.4.0= 升级到 =v0.5.0=。

*** 变更内容
- 更新 =3rd/folly=、=3rd/grpc=、=3rd/hpx=、=3rd/nng= 与 =3rd/taskflow= 的源码版本。
- =builder/folly= 显式使用 =ZETA_OPENSSL_VERSION= 对应的 Conan OpenSSL 静态库，不再将混装有 gRPC BoringSSL 兼容文件的 =ZETA_INSTALL_PREFIX= 强制设为 =OPENSSL_ROOT_DIR=，避免 Folly 配置阶段的 OpenSSL 版本检测失败。
- 第三方 Builder 默认关闭上游 examples 和 tests；HPX 显式设置 =BUILD_TESTING=OFF=、=HPX_WITH_TESTS=OFF=、=HPX_WITH_EXAMPLES=OFF=，同时保持 =HPX_WITH_TOOLS=ON= 以构建 =hpxdep=、=inspect= 并安装 =hpx_stat_viewer.py=。
- HPX 新增 Conan Boost package config 兼容层，补齐 =Boost_<COMPONENT>_FOUND= 变量，使 =inspect= 能正确发现静态 =Boost.Regex=；兼容配置文件同时纳入 configure stamp 依赖。
- =CMakeProjectBuilder= 在配置后刷新构建根目录的 =compile_commands.json= 入口：优先创建相对符号链接，不支持符号链接时回退为复制文件。
- 更新中英文 README，说明托管第三方构建默认关闭 examples/tests，以及 HPX 保留的工具和安装内容。

*** 兼容性与升级说明
- 依赖旧第三方源码行为的本地补丁需要基于本版本记录的 submodule revision 重新检查。
- 编辑器和静态分析工具可统一读取目标构建根目录下的 =compile_commands.json=；各构建类型的原始文件仍保留在对应构建目录中。
- HPX 与 Folly 的默认入口聚焦安装所需目标；需要上游 examples 或 tests 时，应在独立验证流程中显式启用。

** v0.4.0 - 2026-05-18
*** 发布定位摘要
- 新增 =deps= 目标，统一管理外部 ZetaX 项目消费的 Conan 依赖环境。
- 按公共依赖管理能力发布，zeta_forge 从 =v0.3.0= 升级到 =v0.4.0=。

*** 变更内容
- =common/zeta_forge/config.py= 新增 =ZETA_SPDLOG_VERSION=，与 =ZETA_FMT_VERSION= 等公共版本默认值同源管理；升级 =ZETA_BOOST_VERSION= 从 =1.90.0= 至 =1.91.0=（ConanCenter 已收录）。
- =builder/deps= 集中声明 =spdlog=、=fmt=、=GTest= 等公共 Conan 依赖，新增 =boost/{BOOST_VERSION}= 依赖（默认 =1.91.0=，由 =ZETA_BOOST_VERSION= 控制）与 =openssl/{OPENSSL_VERSION}=，并将 CMake package config 安装到 =${ZETA_INSTALL_PREFIX}/lib/cmake/zeta_deps/<BUILD_TYPE>=。
- =builder/deps= 新增 =boost/*:shared=False= 与 =openssl/*:shared=False= 选项，保证 folly-config.cmake 所需的 Boost context/filesystem/program_options/regex/thread 组件均被编译为静态库。
- =builder/deps/zbuild.py= 新增 =install_boost_findboost_compat()= 方法，在 Conan 安装后对 =BoostConfig.cmake= 进行兼容性补丁，为 CMake 3.31+ 的 FindBoost 模块自动设置 =Boost_<COMPONENT>_FOUND= 变量。
- =builder/folly/conanfile.py= 与 =builder/hpx/conanfile.py= 的 =ZETA_BOOST_VERSION= 默认值同步至 =1.91.0=。
- =builder/deps= 同时从 =ZETA_RAPIDJSON_SRC_DIR=（默认 =zeta_forge/3rd/rapidjson=）生成 =RapidJSONConfig.cmake=，以 header-only package 形式统一提供 =rapidjson::rapidjson=，不通过 Conan 管理 RapidJSON。
- =./zbuild.py list/all= 纳入 =deps=，=all= 会优先准备公共依赖环境。
- =cmake_util/find_package/spdlog.cmake= 保留为非 Conan 备用路径，fallback 版本改由 =ZETA_SPDLOG_VERSION= 控制。
- =cmake_util/common.cmake= 移除 =ZPP_USE_CONAN= 与 CPM bootstrap 逻辑，不再设置 =CPM_SOURCE_CACHE=、下载 =CPM.cmake= 或生成项目根目录下的 =cpm_cache*=。
- =cmake_util/find_package= 中的 CPM fallback 模块仅作为历史兼容模块保留，并标记为不属于现代 ZetaX 公共入口。

*** 兼容性与升级说明
- =zpp=、=zeta_trader= 等外部项目不应再维护自己的 Conan 依赖图；应先安装 =zeta_forge deps=，再通过 =find_package= 消费安装环境。
- 找不到 =spdlog/fmt/GTest/RapidJSON/Boost/OpenSSL= package config 时，应重新运行 =./zbuild.py deps --BUILD_TYPE=<type> --install=。
- 外部项目不应再通过 =ZPP_USE_CONAN= 或 CPM fallback 切换依赖来源；如果项目需要 Conan，应在项目 Builder 中显式接入 Conan 流程。

** v0.3.0 - 2026-05-13
*** 发布定位摘要
- 为外部 ZetaX 子项目新增 =add_run_target= 运行入口的公共 Python 复用接口。
- 按公共接口新增版本发布，zeta_forge 从 =v0.2.0= 升级到 =v0.3.0=。

*** 变更内容
- 新增 =common/zeta_forge/run_targets.py=，支持扫描项目 =CMakeLists.txt= 中的 =add_run_target(...)= 调用，解析运行入口名称和预置参数，输出对应 CMake 运行命令，并可直接执行已编译可执行文件。
- =zeta_forge.run_targets= 提供列出运行入口、查找指定入口和在已有 build tree 上直接执行已编译可执行文件的公共函数，便于 zpp 等子项目复用。
- =cmake_util/add_run_target.cmake= 的 CMake 行为保持不变；Python 接口只读取项目源码中的调用信息，不承担 configure 或全量构建。

*** 兼容性与升级说明
- 外部项目可以继续只使用 CMake 层 =add_run_target=；需要统一 CLI 时，可在项目自己的 =zbuild.py= 中接入 =zeta_forge.run_targets=。
- 执行运行入口前仍需要项目已有对应 =BUILD_TYPE= 的 CMake build tree 和已编译可执行文件。

** v0.2.0 - 2026-05-11
*** 发布定位摘要
- zeta_forge 从单一仓库构建入口升级为 ZetaX 公共 C++ 工具链框架。
- 公共路径契约统一为 =$ZETAX_ROOT/zeta_forge=，不再公开推荐额外的 forge/zpp 专用根变量。
- zpp 从 zeta_forge 内置 target/submodule 迁出，作为独立项目复用 zeta_forge 的 Python 构建框架和 CMake helper。
- 遗留独立 =cmake_util= 项目停止作为更新点，最新内容由 =zeta_forge/cmake_util= 接管维护。

*** 变更内容
- 将工具链公共逻辑从顶层入口脚本抽象到 =common/zeta_forge= 库模块，提供根路径发现、环境注入、源码目录解析、CMake/Conan 构建生命周期和 dispatcher。
- =./zbuild.py all= 继续调度 forge 管理的基础依赖，顺序为 =grpc -> hpx/nng -> folly=；=zpp= 不再是 forge 内置 target。
- 新增 =cmake_util/=，保留公共 CMake helper、依赖查找脚本和 =add_run_target=，移除遗留 =cbuild*= 快捷入口。
- =RepoConfig= 注入 =ZETAX_ROOT=、=ZETA_BUILDER_DIR=、=ZETA_3RD_DIR=、=ZETA_CMAKE_UTIL_DIR=、=ZETA_INSTALL_PREFIX= 等派生环境。
- =common/prepare_debian.sh= 不再把私有 =zsa= 作为公共必需前置条件；缺少 =python3= 时提示公共用户需要先准备的基础 Debian/Ubuntu 构建环境。
- 更新 README、架构设计文档和第三方系统接入说明，明确 zeta_forge 的三项职责：构建工具链、版本协调、外部系统复用框架。

*** 兼容性与升级说明
- 公共用户应使用 =ZETAX_ROOT=/path/to/workspace=，并保持 =$ZETAX_ROOT/zeta_forge= 的标准布局。
- 旧的 =./zbuild.py zpp= 不再支持；zpp 应在 =$ZETAX_ROOT/zpp= 中使用自己的 =./zbuild.py=。
- 外部项目可继续覆盖 =ZETA_<NAME>_SRC_DIR=、=ZETA_3RD_DIR=、=ZETA_INSTALL_PREFIX=，但不应依赖旧的 forge 专用根变量。
- 项目级构建逻辑应留在项目仓库自己的 =builder/= 中，公共生命周期和 CMake helper 由 zeta_forge 提供。

*** 验证
- =python3 -m py_compile zbuild.py common/zeta_forge/*.py common/prepare_debian.py builder/*/zbuild.py= 通过。
- =./zbuild.py list= 通过，目标列表不包含 =zpp=。
- 独立 zpp 使用 =$ZETAX_ROOT/zeta_forge/cmake_util= 完成 =Debug --no-tests --no-examples --rebuild= 构建验证。

*** 版本更新规则
- 修改公共构建入口、CLI 参数或环境变量语义时，需要同步更新 =VERSION= 和本文件。
- 修改 =common/zeta_forge= 中可被项目复用的公共接口时，需要记录兼容性影响。
- 修改 Conan 依赖版本、默认 C++ 标准、安装前缀策略或构建默认值时，需要记录升级说明。
- 修改 submodule revision、=3rd/*= 管理策略或 =cmake_util/= 公共 helper 行为时，需要记录变更内容。
- 新增面向外部项目的接入方式、兼容性约束或迁移要求时，需要记录接入说明。

** v0.1.0 - 2026-05-11
*** 发布定位摘要
- 首次明确 zeta_forge 作为通用工具链框架的版本基线。
- 定义 zeta_forge 的用途：=3rd/*= 共享编译工具链、外部项目可复用的工具链框架、工作区版本协调层。
- 该版本未作为独立 release 发布，后续结构调整并入 v0.2.0。

*** 变更内容
- 建立 =VERSION= 与版本记录文件。
- 初步建立架构设计文档和第三方系统使用说明。
- 明确版本协调范围包括 submodule revision、Conan 依赖版本、共享构建默认值和项目级构建配方。
