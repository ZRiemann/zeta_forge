** v1.0.0 - 2026-09-23
*** Release Summary
- Establish a unified, discoverable Forge build contract, replacing directory-specific scripts and legacy dispatch with products and engineering units.
- Separate build, staging and explicit publication lifecycles with shared CMake, Rust and Gradle engines.

*** Changes
- Unify =list=, =metadata=, =build=, =install=, =check=, =test=, =clean= and =rebuild= under root =./zbuild.py=, with target selection, profiles and side-effect-free =--dry-run=.
- Replace individual native dependency entrypoints with project definitions; centralize dependency order, target capabilities and error semantics in the shared CLI, operation model and CMake/Rust/Gradle engines.
- Write build outputs to project-local staging isolated by profile/target; =install= publishes only explicitly selected, successfully built targets and fixes installed CMake and pkg-config metadata prefixes.
- Migrate Rust governance to baseline =1.97.1-r2=, remove project-level default profiles and select build profiles through the unified command contract.
- Add build-contract, native-delivery and install-safety tests; synchronize English/Chinese architecture, usage and migration documentation.

*** Compatibility and Upgrade Notes
- Remove support for legacy flag-only, stack-first and alias commands and standalone =builder/*/zbuild.py= entrypoints; callers must migrate to =./zbuild.py <command> [deliverable ...] [--profile release|debug]=.
- =install= no longer builds implicitly or publishes every dependency; first complete =build= with the same profile, then explicitly select the targets to publish.
- Rust projects must adopt =1.97.1-r2= and remove =default-profile= from =zeta-rust.toml=.
